# 个人全方位展示网站｜产品文档

## 1. 项目概述

### 1.1 项目名称

**YU JUNXI / Product Lab**

### 1.2 产品定位

一个面向求职场景的个人品牌与作品集网站，用于展示余俊曦的教育背景、产品经历、AI 项目、专业能力，以及通过 Vibe Coding 将想法快速转化为可交互产品的能力。

网站不只是在线简历，而是一个“可阅读、可体验、可验证”的个人产品空间。

### 1.3 核心定位语

> 把复杂问题，做成真正可用的 AI 产品。

辅助定位：

> AI 产品经理｜产品工程实践者｜交通科技研究者

### 1.4 当前背景

余俊曦具备交通运输规划与管理、企业服务产品、AI 应用和数据分析的复合背景，经历覆盖：

- 京东 AI 外呼分析、客服与搬家业务产品；
- 企业知识库与 RAG 产品；
- AI 数字人与 AIGC 内容生产；
- 高速公路通信图纸 AI 识别系统；
- 交通规划、交通数据分析和城市物流研究；
- 使用 Vibe Coding 完成前后端产品验证。

## 2. 产品目标

### 2.1 一级目标

让招聘方在 3 分钟内理解：

1. 我是谁，适合什么岗位；
2. 我做过哪些真实、有结果的产品；
3. 我如何解决问题，而不仅仅是罗列技能；
4. 我是否具备从需求到 Demo 的完整闭环能力。

### 2.2 二级目标

- 建立“AI 产品经理 + 产品工程实践者”的个人品牌；
- 将简历中的经历转化为具备上下文的案例；
- 通过可交互 Demo 展示 Vibe Coding 能力；
- 降低招聘方获取简历、项目和联系方式的成本；
- 为后续持续添加项目、文章和实验提供可扩展结构。

### 2.3 非目标

- 不替代正式的招聘系统；
- 不公开身份证、紧急联系人、家庭信息、详细住址等私人数据；
- 不公开企业内部敏感数据或未经授权的生产页面；
- 第一版不追求复杂账号体系和后台 CMS。

## 3. 目标用户

### 3.1 主要用户：招聘方 / 面试官

关注：

- 求职方向和个人定位；
- 代表性项目与业务结果；
- AI、产品、数据和工程能力；
- 教育经历和奖项；
- 是否能够独立推动项目落地。

目标体验：

> 进入网站后快速建立信任，并愿意下载简历或联系候选人。

### 3.2 次要用户：产品、技术或行业从业者

关注：

- AI 产品案例；
- RAG、Agent、OCR、多模态等实践；
- Vibe Coding 的产品化使用方式；
- 交通专业和 AI 应用的结合。

目标体验：

> 愿意深入阅读项目，并通过实验室体验具体产品。

### 3.3 潜在用户：合作方 / 导师 / 同学

关注：

- 研究方向；
- 专业能力；
- 项目合作经历；
- 联系方式。

## 5. 页面规划

### 5.1 首页

**页面目标**：让招聘方快速理解个人定位，看到核心证据，并进入项目或简历页面。

**核心模块**：

1. 顶部导航：Home / Resume / Projects / Lab / Contact；
2. Hero：一句话定位、简介、CTA 按钮；
3. Product Console：用动态产品工作流体现“从问题到产品”；
4. 数据指标：研究生在读、8 项迭代需求、6 个业务系统、5.3 万月处理工单；
5. 精选案例：3 个高价值项目；
6. 能力矩阵：产品、AI、工程、行业；
7. 联系 CTA：鼓励查看简历或联系。

### 5.2 简历页

**页面目标**：完整介绍学历、实习、项目、奖项和能力，但避免复制传统 Word 简历的冗长格式。

**内容优先级**：

1. 个人定位与职业摘要；
2. 京东及 AI 产品经历；
3. 代表性项目；
4. 教育背景；
5. 奖项与荣誉；
6. 技能与校园经历。

**关键交互**：

- 简历下载 / 打印；
- 时间线展开；
- 按类型筛选经历；
- 点击项目进入项目详情；
- 移动端折叠内容。

### 5.3 项目页

每个案例采用统一模板：

1. 项目摘要；
2. 业务背景；
3. 核心问题；
4. 我的角色；
5. 产品方案；
6. AI / 技术实现；
7. 结果与指标；
8. 复盘与下一步。

| 项目 | 主要证明能力 |
| --- | --- |
| AI 外呼智能分析平台 | 企业级 AI 产品、0-1、数据闭环 |
| 通信图纸 AI 录入系统 | 多模态 AI、OCR、知识库、复杂系统 |
| 筑云智库 | RAG、Prompt、MVP、结构化输出 |
| 宁姐姐数字人 | 用户调研、AIGC、技术选型、SOP |
| 地下物流系统 | 建模、优化、研究转产品 |

### 5.4 产品实验室

**页面目标**：通过可操作 Demo 证明“能够把想法做出来”，而不是只展示工具名称。

#### 实验 A：JD 岗位匹配助手

输入岗位描述，输出岗位类型判断、匹配能力、推荐项目和面试准备建议。第一版可使用本地规则和模拟结果，后续再接入真实模型。

#### 实验 B：AI 外呼 Badcase 分析

用户选择一条模拟通话，查看通话摘要、失败原因、风险标签和改进建议。

#### 实验 C：通信图纸识别流程

使用模拟图纸缩略图展示图像预处理、区域识别、OCR / 图元检测、结构化输出和异常标注。

## 6. 内容策略

### 6.1 内容原则

- 先结论，后过程；
- 先成果，后职责；
- 用案例证明能力；
- 用真实数字，但标明上下文；
- 生产数据全部脱敏；
- 不夸大未完成的能力。

### 6.2 统一项目描述模板


auto
背景：为什么做？
问题：原流程有什么痛点？
角色：我负责什么？
方案：我如何拆解和设计？
实现：AI / 数据 / 产品如何协同？
结果：带来了什么变化？
复盘：下一步怎么改？

### 6.3 公开内容边界

不展示：身份证号码、紧急联系人、家庭成员、婚姻/身高/体重等非求职必要信息、真实手机号和私人 QQ、企业内部数据、生产接口和未脱敏截图。

可展示：姓名、城市、邮箱、学校、专业、研究方向、脱敏后的项目流程和模拟数据、代表性成果和可验证 Demo。

## 7. 视觉与交互设计

### 7.1 设计关键词

专业、克制、数据感、产品实验室、复杂系统、可验证。

### 7.2 视觉方向

- 深海军蓝作为主背景，象征系统与基础设施；
- 米白和浅灰承载正文，保证可读性；
- 青绿色表示 AI / 成功状态；
- 蓝色表示信息与链接；
- 橙色表示提醒和行动按钮；
- 使用细线网格、流动连接线和数据卡片增强系统感。

### 7.3 交互原则

- 动效服务于理解，不做无意义炫技；
- 所有核心内容在 1～2 次点击内可达；
- 桌面端与移动端均可使用；
- Demo 必须有清晰状态：待机、分析中、完成、异常；
- 允许用户跳过复杂交互直接阅读项目结果。

## 10. 验收标准

### 内容验收

- 招聘方在首屏能看到身份、方向和代表能力；
- 教育、实习、项目、奖项均有独立内容区；
- 项目描述包含背景、角色、方案和结果；
- 网站不包含身份证、紧急联系人和家庭信息。

### 交互验收

- 顶部导航可以定位到所有核心栏目；
- 项目卡片可以展开详情；
- 实验室 Demo 可以完成至少一次可见的输入—分析—输出；
- 简历按钮可以触发打印 / 保存为 PDF；
- 移动端无横向溢出。

### 视觉验收

- 信息层级清晰；
- 文本对比度足够；
- 动效不影响阅读；
- 重要内容不依赖 hover 才能访问；
- 页面加载后不出现未样式化内容。

## 11. 成功指标

第一版上线后重点观察：首屏停留时间、项目详情打开率、简历下载 / 打印点击率、产品实验室启动率、联系方式点击率和移动端访问完成率。

## 12. 后续内容补充清单

1. 完整奖项名称、等级和年份；
2. 京东实习的准确起止时间；
3. 可公开的项目截图或脱敏素材；
4. GitHub / Gitee / 个人邮箱链接；
5. 是否需要英文版简历；
6. 是否展示头像；
7. 是否接入真实 AI API；
8. 是否制作独立 PDF 简历。
